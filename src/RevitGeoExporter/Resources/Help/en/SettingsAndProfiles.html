Configuration

Settings and Profiles

The settings hub separates stable global defaults from project-specific mappings, so teams can keep reusable settings without overwriting project decisions.

Global defaults

  • Default output folder and UI language.
  • Shared CRS / EPSG defaults, including the CRS preset list.
  • Diagnostics, GIS package, package legend, and geometry repair defaults.
  • Basemap source settings for preview.

Project data

  • Floor type to category mappings.
  • Room category overrides.
  • Family category overrides.
  • Accepted opening families — family names that may export as openings, and that also drive the Fixtures layer (for example ticket-gate families).

Profiles

Three independent profile families are managed from the settings hub. Keep them in mind when something in the export dialog seems to be set globally but isn't taking effect — the active profile may be overriding it.

  • Export profiles — full snapshots of the export dialog (selected layers, coordinate mode, advanced toggles). Save one per recurring handoff.
  • Schema profiles — define which fields appear on each output layer and how custom attributes are named. The active schema is shown in Advanced options.
  • Validation policy profiles — decide which validation findings block export versus warn. Tighten or relax checks per project without changing the dialog.

Import, export, and reset

Each scope can be imported, exported, or reset independently. If a saved file is incomplete or malformed, the status area explains what was ignored and safe defaults are used where possible.
